**Runs:** dispatched

Improve the resolved text in one pass. Stop with the edited artifact or, for pasted text, return the rewrite without touching files.

This skill fills the **edit lane** required by `~/.kk-flavor/standards/human-writing.md` → **Edit pass**.

Run under `~/.kk-flavor/standards/skill-protocol.md`. Unit noun: `Artifact`. Dispatch as `kk-edit` under `~/.kk-flavor/standards/model-policy.md`.

## Scope

Resolve the requested files or text and its audience. A directory scope includes prose documents; a code scope includes comments and docstrings only. For the outward-artifact trigger, scope the pass to the artifact being prepared. Preserve quoted material, code blocks, command output and code behavior.

Agent instructions may receive wording-only edits here. Deleting an obligation, changing a trigger, resolving conflicting rules or restructuring a skill goes to the instruction or skill-structure lane before mutation. Those lanes can apply this prose pass inline after settling semantics.

## Edit

Read `~/.kk-flavor/standards/writing.md` for clarity and density. For outward communication and code comments, also apply `~/.kk-flavor/standards/human-writing.md` for voice and its artifact-specific form. For a body, a comment or a reply you are preparing, run `~/.kk-flavor/skills/kk-edit/scripts/voice-check.sh --profile=prose` over it and make the edits it names. Add `--kind=pr-body` for a PR body and `--kind=ticket` for a ticket, so the run reads the author's sentences and leaves the template's alone. A description is cut by sentence, by the test `~/.kk-flavor/standards/human-writing.md` → **Change descriptions (PRs)** states, and never to a length. The audience selects the guidance; the human need not choose a mode.

Cut repetition and recoverable filler. Use concrete words and readable sentences. Keep deliberate repetition where a reader needs a constraint at its point of use. Preserve required facts, numbers, names, negation, exceptions, tense, conditionality, commitments, severity and unresolved questions. Keep the source's wording for unresolved status if paraphrasing would attribute knowledge, intent, a response or a decision to someone. A future commitment is not a present fact. If a cut may change meaning, keep it or return a proposal.

For code comments, write every block again from the code. The lane decides each block itself, and it returns no decision about a comment to the human. Read the refactor lane's comment lines by script. `grep -E '^Comment [0-9]+/[0-9]+ ' <the return>` counts them against the blocks. `grep -E '^Comment .* \| (blocked:|stays: .*(licence|scope rule|confirmation))' <the return>` finds the ones to refuse. It matches `licence`, the flavor's word for a permission, and `confirmation`, the noun a refusal names. Run 10's code spelled its DRM license `license`, and run 13's fact said a platform cannot confirm a type. Patterns matching those words refused both lines. Refuse a line with any verdict outside `carried by` and `stays:` as well. An existing message a human sees already carries the what, so the lane leaves its wording as it stands, and the why stays the note. Then run `comment-run.sh carried --run=<run> --run-dir=<dir> --archive=<archive> <the lane's return>`. Later runs then offer a carried block's site no more while its carrier stands. A lane never edits a comment line, and `carried` refuses a file where it did. Where a ruling reverts a lane edit, run `comment-run.sh revert --run=<run> --run-dir=<dir> --archive=<archive> <file>`. It restores the whole file as the writers left it, so a later accepted change to that file goes too, and withdraws the run's carried records for it. After the lane lands a rename, run `comment-strip.sh --rename=<old>=<new> --archive=<archive> <file>` over each file of the change set, and a block it rewrote needs no writer. Then run `~/.kk-flavor/skills/kk-edit/scripts/voice-check.sh --carriers=<the facts dir> <the caller's revisions>` over the tree the lane left. Each finding names a landing that holds the fact where code never reads it. It is the block's prose in a string, a name that is a sentence, or an unread field or constant. Refuse the `carried by` lines of that file with the finding quoted, so the lane undoes the landing and returns a real carrier or `stays:`. Refuse a `blocked:` on a comment block. Refuse a `stays:` too where its reason names a licence, a scope rule or a confirmation. Dispatch the lane again for those blocks with `~/.kk-flavor/standards/comments.md` quoted, twice at most. A block still refused after that is a tool finding in the run's report, by its line, and never a question to the human. A block refined in place is judged against the block it replaces, and three rounds of that produced comments no reader could follow. The lane runs three steps over each changed source file, in this order.

1. **Strip.** From the tree at the change's head, run `~/.kk-flavor/skills/kk-edit/scripts/comment-run.sh seed --run-dir=<dir> --archive=<archive> --range=<base>..<head> --heads=<earlier heads> --contradictions=<tsv>`. `<dir>` is a directory of your own under the scratch dir, and `<archive>` is the directory this change set keeps across runs. `--heads` seeds the archive from each earlier head of the change, and the tsv holds each claim review found false: path, claim, run and sentence. The stage refuses a tree off the head or with changes of its own. It strips every changed file with `comment-strip.sh`, removing every comment block, one from before the change included. It writes each to a facts file headed by its site, and prints the sites and the count of blocks kept. It calls no model. A comment the toolchain reads stays, and the strip names it on stderr. A block this lane wrote on an earlier run stays too, byte for byte, while its record holds, and the strip names it on stderr. A changed rule, a changed declaration or body, or a contradiction reopens it. Blocks written before the lane archived records carry none, so the first run after this rewrites them once more. A run over an unchanged tree after that rewrites no block.
2. **Write.** Run `comment-run.sh prompts --run-dir=<dir>`. It decides the writers from the sites, at most three at a time. A file stays with one writer. A directory stays with one writer where it fits. Past three writers' reach it prints batches, and each batch waits for the batch before it. It fills `~/.kk-flavor/templates/spawn-prompt.md` for each writer, and names the brief and `~/.kk-flavor/standards/comments.md` without quoting them. The writer reads both in its first turn, and no other file under the rule directories. The stage records the rules' sum in `<dir>/rules.sum`. A later prompt of the run refuses on a changed sum, and so does `archive-written`. The emphasis slot quotes `<dir>/licence.txt` where the human gave their own words for this run, and it reads `none` otherwise. The runner writes no licence text of its own. Dispatch each prompt as written to the `comment-writer` agent under `~/.kk-flavor/standards/model-policy.md`, with the prompt's text as the task message. A writer told to read its prompt from a file reads it twice. Bootstrap mounts that agent for Claude only. Where Claude's mount is missing, `prompts` and `loop` say that a writer dispatched there starts as a general agent. Codex has no such agent, so a Codex run's report names its writers as general agents. That agent's tools are Bash, Read, Edit, Write and Grep, and it loads only its prompt: MCP servers, skills and instruction files stay out. The writer writes each block with the Edit tool and its whole return to `<dir>/return-writer-<name>.md`. It writes a block from the code or `none` per site, and `none` is its default. Count its `Block` lines against the sites, one per site number and location with the last verdict winning. A site answered at several declarations, or answered twice, is one site. It returns `stale`, `carried by`, `rename`, `belongs at`, `does not fit` and `for the PR body` lines. A `belongs at <file>:<identifier>: <fact>` line is a fact whose bearing is at a caller in another file of the change set. Hand it to that file's writer as a record, under `bears_on: <identifier>`, in the same round where that file is in the set. Where the set holds no such file, it goes to the caller with the `does not fit` lines. Then run `comment-run.sh taint --ledger=<the writer's queue ledger> <its transcript>` for each writer. It fails a writer whose first turn did more than read both rule files whole after its prompt was written. It also fails a writer that read any other file under the rule directories. A writer failed on its reads is handled like a tainted one, with its sites stripped again and a fresh writer dispatched. A transcript the stage cannot parse fails the same way, so a Codex run reads its writers' first turns by hand. Run `comment-run.sh usage <the transcripts>` for the report's tokens, calls and wall time per writer. The strip clears the tree and leaves the history, so a writer that read the range saw the blocks it was sent to replace. A hit counts where it reads a revision of a file the writer still writes to afterwards, and its output holds a comment line. The files the writer writes to are the ones its ledger lists, and its last write to a file is its ledger entry for it. A shell line naming a file, such as a lint run's `2>&1` or an append to the ledger, writes no block. A read after the writer's last write to that file is clean. A chained command's output mixes its parts, so the stage prints it to read by hand and never counts it. A diff with no range shows HEAD's blocks against the stripped tree, and it counts. A write by shell script is reported, because writes go through the Edit tool. Run 11's writer read the merge-base file after its first write and before its last. Run 9 re-stripped three writers for that and lost 45 sites. A hit that counts is a tainted run: strip those sites again and dispatch a fresh writer for them.
3. **Voice.** Run `~/.kk-flavor/skills/kk-edit/scripts/voice-check.sh` over the caller's revisions. **Every finding it prints is an edit you make**: strip that block and dispatch the writer for it. The shapes it names are the **House voice** group of `~/.kk-flavor/standards/human-writing.md` → **AI tells**, and the form it holds you to is `~/.kk-flavor/standards/comments.md`. No finding is kept by a list. One that must stand is a defect in the check. The check is measured on the reviewed set and fixed there, or it is demoted to report-only. Once the files are clean, run `comment-run.sh archive-written --run=<run> --archive=<archive> --run-dir=<dir>`, which reads the writers' return files there. It archives each block a writer wrote with its record, and a block holding a summary alone with an empty record. Then `comment-run.sh keep-test --archive=<archive> <the changed files>` prints the blocks the next run keeps, and the reason each other block will be written again.

Three bounds, and a model votes on none of them. The writer's `none` default and its two-rewrites-then-`none` rule bound how much gets written. The voice check bounds the register. The refactor lane's `carried by` line bounds placement. A judge kind that labelled every block was measured against this lane and dropped. `ai/tools/reader-judge/eval_test.go` holds what it scored.

Then run `~/.kk-flavor/skills/kk-edit/scripts/voice-check.sh --density` over the same revisions and report its figure. The figure gates no edit. Return the writer's routed lines with it. `carried by` and `rename` go to the refactor lane, and `stale` to correctness review. `for the PR body` goes to the caller for the change's description, and `does not fit` to the caller for the human. A `does not fit` fact is about the world, and it never becomes a paragraph of the body. The refactor lane lands a carrier or returns `stays:`, and a fact about code with a declaration never goes to the body. Comment truth belongs to correctness review and placement to refactor.

A code-review finding on a comment line goes back to the writer at that site once. Run `comment-run.sh loop --run-dir=<dir> --archive=<archive> --run=<run> --contradict=<the review's sentence> <path>:<line> <the review's sentence>` once per round, with every site of the round, and dispatch its one prompt. Run `taint` and `usage` on the loop writer's transcript as on a writer's. Leave out `--contradict` where the review found no claim false. It records the contradiction by the block's line first, strips that site alone and adds the review's sentence under `# code review:` in its facts file. It then writes the loop writer's prompt with the run tree's fingerprint, and prints its path. The strip offers the claim with a `contradicted:` line in this loop and in every later run. The writer drops a clause the code contradicts where it cannot tie that clause to the code. Review leaves a claim about the world, such as a device rejecting a tier, to its author. A lane keeps its own doubt out of every block.

## Verify and return

Compare the rewrite with the source for lost meaning and accidental code changes. Check links or syntax affected by the edit. Account for the scoped artifacts and return only unresolved proposals and the protocol's required evidence. A wording edit creates no second editorial lane.
